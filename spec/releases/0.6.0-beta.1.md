## Summary

`0.6.0-beta.1` is the first preview of the 0.6 line. It focuses on a unified
Agent management workbench, broader native Agent asset support, provider/model
configuration, official Codex account switching, and file-first local storage
with stronger migration and recovery behavior.

## User-Facing Highlights

- Unified Agent workspaces for Skills, MCP, Plugins, Rules, providers/models,
  configuration files, quotas, and session history.
- In-place selection dialogs for adding Agent Skills, MCP servers, and Plugins.
- Broader Claude Code, Codex, Antigravity, Kimi Code, OpenCode, Pi, Grok Build,
  Qoder, OpenClaw-family, Cursor, and related Agent target coverage.
- Shared provider/model forms with native connection and model probes, explicit
  error explanations, activation safeguards, and account-aware credentials.
- Encrypted Codex official-account snapshots that switch by replacing the
  active `auth.json` without replacing official model or provider settings.
- Unified quota presentation for rolling, weekly, monthly, and total limits,
  including compact circular window indicators and provider membership tiers.
- File-first canonical local authority, rebuildable SQLite catalog behavior,
  journaled recovery, migration safety, and bounded recovery artifacts.
- Windows upgrade/restart recovery now bounds the complete canonical checkpoint
  and temporary SQLite hierarchy, reclaims owned sidecars/locks, and verifies
  two clean launches against the same upgraded profile before publication.

## Release Surface Decisions

- Root, Desktop, CLI, self-hosted Web, Cloudflare Worker, Mobile package, Expo
  metadata, and CLI runtime report `0.6.0-beta.1`.
- Private shared packages retain their independent `0.1.0` versions.
- Public stable badges, default downloads, and website generated metadata remain
  on published stable `0.5.9` until a later stable release is published.
- README preview links may target this explicit prerelease while stable badges,
  default downloads, and update behavior continue to target `0.5.9`.
- Existing public screenshots are retained because neither `docs/imgs/` nor
  `website/public/imgs/` contains an Agent workspace, native quota menu or Agent
  config-editor counterpart. Isolated Electron E2E screenshots verify the
  current Agent/config surfaces without replacing an unrelated stable image.

## Withdrawal Incident

- A Windows user upgrading from `0.5.9` received
  `EPERM: operation not permitted, fsync` before the application window loaded.
- The affected startup path created a pre-upgrade SQLite safety image and then
  attempted to flush a file descriptor opened read-only. Windows requires write
  access for `FlushFileBuffers`, which Node uses for `fsync`.
- Run `31712011544` built Windows x64 and arm64 installers but did not launch a
  packaged Windows application. Its green status therefore did not prove
  Windows startup compatibility.
- The replacement candidate passed the Windows packaged upgrade cold start and
  the complete build matrix, then was explicitly promoted on 2026-08-19 after
  all replacement artifacts and public boundaries were verified.

## Post-Publication Windows Restart Replacement

- Reported on 2026-08-20: an overwrite installation opened successfully once,
  but the next Windows launch failed before the main window with
  `SQLite3Error: Could not open the database` on a canonical catalog
  `.db.stage-<pid>-<uuid>` path.
- The release smoke proved only the first upgraded launch. That launch can
  defer canonical authority until renderer persistence migration completes,
  so it did not exercise the failing second-launch checkpoint path.
- The complete checkpoint ancestor and temporary SQLite leaf hierarchy now uses
  bounded UUID names. Task-owned database cleanup includes rollback/WAL
  sidecars and the adjacent `node-sqlite3-wasm` `.lock`; related external Agent
  database failure paths close every opened handle.
- The public prerelease was replaced on 2026-08-20 only after local 42/42,
  manual full-platform, tag-triggered full-platform, real Windows x64
  two-launch, macOS signing/notarization, asset, updater-manifest, and GHCR
  isolation gates passed.
- Because the replacement keeps version `0.6.0-beta.1`, clients that already
  installed the affected build will not treat it as a newer automatic update.
  Those users must manually download and overwrite-install the fixed package,
  then quit normally and launch once more; fresh downloads receive the
  replacement assets.
