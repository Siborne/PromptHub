# PromptHub 0.6.0 Release Record

## Release

- Version: `0.6.0`
- Tag: `v0.6.0` (not created)
- Date: Unreleased
- Channel: Stable
- Status: Preparation

## Preparation Scope

- The first release candidate used `0.6.0-beta.1`. The current candidate uses
  `0.6.0-beta.2` across Root, Desktop, CLI, self-hosted Web, Cloudflare
  Worker, Mobile, and Expo metadata. Stable promotion will replace that
  identity with `0.6.0`.
- Private shared packages retain their independent `0.1.0` package versions.
- Public website badges, introductions, and download URLs continue to point to
  the latest explicit stable release record, currently `0.5.9`.
- Localized README stable labels and download links remain on `0.5.9` until
  signed artifacts and other distribution outputs have been published.
- Local storage adopts versioned file-first canonical authority for Prompt,
  Folder, Tag, relation, output-format, Skill, Rule, MCP, Plugin, Agent, and
  Generation resources. SQLite is a staged rebuildable catalog plus explicitly
  classified same-device operational/server-compatible state.
- Renderer durable state is migrated to main/Core owners, secrets are isolated,
  restore/root changes are journaled, safety points and recovery artifacts are
  bounded, and portable snapshots verify canonical/logical consistency.
- The shared SQLite migration foundation is verified against tagged `v0.4.7`,
  `v0.4.8`, `v0.5.1`, and `v0.5.2` fixtures. Historical issues #89, #97, and #98
  remain in progress until their exact path/portable/upgrade-snapshot application
  fixtures converge under `legacy-upgrade-recovery-audit`.

## Publication Gates

- Complete the `0.6.0` changelog from the final release contents and replace
  `Unreleased` with a dated stable entry.
- Promote `0.6.0` from `preparation` to `stable record` in the release index
  only after public artifacts are available.
- Run `pnpm verify:release` before tagging or publishing.
- Build, sign, notarize, and verify required desktop artifacts through the
  standard release workflow.
- Publish and verify CLI, self-hosted Web, Worker, Mobile, release assets, update
  manifests, and configured mirrors as applicable.
- Refresh public website metadata and localized README release copy only after
  the corresponding public artifacts are available.

## Rollback

Before beta.2 publication, restore product manifests to `0.6.0-beta.1` and
remove the beta.2 candidate record. The public website can always be regenerated
from the unchanged `0.5.9` stable record. This release identity change
introduces no database schema, user data, or remote state.
