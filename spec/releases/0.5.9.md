# PromptHub 0.5.9 Release Record

## Release

- Version: `0.5.9`
- Tag: `v0.5.9`
- Date: 2026-07-11
- Channel: Stable

## Summary

`0.5.9` is a stable release focused on Plugin and MCP management, Agent asset sync, Skill source update reconciliation, custom Prompt output format sequences, signed macOS delivery and in-app updates, Grok Build support, complete CLI resource workflows, network configuration, and safer shared database access.

The final stable tag replaces the previously published `v0.5.9` release head so its existing release record and assets include the post-release Skill update, YAML fidelity, AI protocol, and module-boundary corrections.

## User-Facing Highlights

- Plugin management is promoted into the stable release with My Plugins, Plugin Store, Agent Plugin, install/detail flows, snapshots, source update review, static safety assessment, and child Skill/MCP import.
- MCP management is expanded with the MCP workspace, official template store, Agent target distribution, health checks, selective `.env` import, CLI MCP commands, and resync design.
- Agent asset sync now covers My Skills, My MCP, My Plugins, and Rules across self-hosted sync and backup/restore flows.
- Skill source updates use SHA-256 package fingerprints and three-way reconciliation to reduce false local-change and false up-to-date reports.
- High-risk Skill source updates now return a reviewable report. Users can approve one exact staged package or persist trust only for an exact repository, branch, and directory source; blocked findings, path traversal, and invalid package structures remain non-overridable.
- Staged self-hosted Skill packages use a bounded source-address check so an unreachable Gitea host is reported as provenance context instead of freezing the update flow.
- SKILL.md YAML frontmatter uses one semantic parser and normalizer across editing, hashing, and source update flows so valid block, nested, and `allowed-tools` fields are retained.
- Plugin updates now require a review/confirmation step before overwriting local content.
- Windows and Agent platform compatibility now includes more paths and platform metadata for Hermes, Trae Work, WorkBuddy, QClaw, and `%LOCALAPPDATA%`.
- Grok Build is available as a built-in Agent target with its official icon and verified `~/.grok` Skill, Rules, configuration, and MCP discovery paths.
- CLI coverage now includes the primary Prompt, Folder, Skill, Rules, MCP, Plugin, and Workspace resource workflows.
- macOS release packaging requires Developer ID signing, notarization, artifact verification, and signed ZIP metadata for direct-install in-app updates.
- CLI and Desktop coordinate writes to the shared SQLite database, recover ownerless legacy locks only after Desktop wins the single-instance gate, and refresh renderer data after returning to the application.
- Prompt output formats can be composed as ordered Prompt-reference sequences and are preserved by backup and restore.
- Core, desktop, and Web now share AI protocol endpoint/auth derivation, preventing provider endpoint and header behavior from drifting across products.
- No source or test file exceeds the 2,000-line hard limit. Larger legacy files are ratcheted through the checked-in size baseline while future files are limited to 1,500 lines by default.

## Release Surface Decisions

- Package versions and CLI runtime version were bumped from `0.5.9-beta.2` to `0.5.9`.
- `CHANGELOG.md`, website changelog, website generated release metadata, root README, and localized README files are aligned to `0.5.9`.
- Stable direct download links point at GitHub Latest stable asset filenames for `0.5.9`; fixed CDN mirror filenames remain deferred until mirror sync is verified.
- The previous `0.5.9-beta.2` prerelease remains linked as a historical preview row in README download tables.
- Screenshots were not regenerated during this release-prep pass; README screenshot copy now describes the current `0.5.9` stable surfaces.
- The stable tag is intentionally moved from the earlier release-preparation commit to the final `0.5.9` release head so the published artifacts include the late CLI, updater, Grok Build, database coordination, and verification fixes.
- The replacement release updates the existing published `v0.5.9` record in place and replaces its assets, preserving the stable release URL for installed clients and external links.
- A replacement with the same version only refreshes new downloads and manual reinstalls. The updater intentionally requires a strictly higher semantic version, so already installed `0.5.9` clients require `0.5.10` or later for an in-app update.
