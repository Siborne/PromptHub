# Desktop Backup And Historical Recovery Completion

## Problem

The Data settings drop target is labelled as backup recovery, but it accepts
only exported JSON/GZIP/ZIP archives. SQLite backups generated by database
migration and recovery are rejected. The history scanner also lists only the
legacy `backup-before-*.db` pattern, so newer `backup-*`, `pre-recovery-*`,
integrity, and migration-conflict backups remain inaccessible from the UI.
Follow-up Windows reports show that the historical recovery scanner also
discards explicitly selected directories when they contain durable MCP, Rule,
Plugin, config, or media files but no readable Prompt/Skill database rows. The
recovery dialog and backup copy describe only Prompt, Folder, and Skill data,
even though full exports already carry additional agent assets.

## Scope

- Route dropped PromptHub SQLite backup files to the recovery candidate preview.
- Scan every PromptHub-generated standalone database backup filename.
- Preserve archive import as a separate merge workflow.
- Require candidate inspection and explicit user confirmation before replacing
  the active database.
- Detect, preview, and restore all durable PromptHub data classes from manually
  selected historical directories, including MCP, Rules, Plugins, config, and
  media.
- Make SQLite backup selection consistent between the file picker and drag
  target.
- Expose MCP and Plugin export scopes independently and show the real full
  backup/import inventory in the UI.

## Risks And Rollback

SQLite restore replaces the active database. The existing recovery flow must
create a pre-recovery copy first and reject unreadable, empty, symlinked, or
unrecognized files. The change can be rolled back without a data migration.
Directory recovery remains merge-only for file data and must not overwrite
existing files. Cache, logs, backups, and Electron runtime storage are not
treated as portable business data.
